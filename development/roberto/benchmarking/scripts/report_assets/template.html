03 / INTERPRET THE EVIDENCE
What is held fixed, and what differs.
The campaign records its physical cases and effective solver configuration alongside the source it executed.

  
Accuracy and convergence
Analytical errors are evaluated independently of the numerical residual. Cell-reference errors and dense analytical curves have different roles: the former assess the computed state, while the latter show the continuous physical branch.
A converged discrete solution may retain a known sonic-limit discrepancy or shock smearing. Known limitations are displayed rather than hidden by weaker stopping tolerances.
Boundary defects, integrated conservation defects, finiteness, and admissibility remain separate audits. Returning an array or reaching an iteration limit does not establish convergence.
Timing boundary
Steady solves start from identical cold physical conditions, with a complete excluded warmup before measured repetitions. Kernels are reused, device work is synchronized, and measured methods run sequentially.
Setup, analytical reference construction, JIT compilation, external analytical/comparison audits, and presentation are excluded from timed solves. The production driver's ordinary final checks remain inside its measured solve, together with rejected steps and controller/monitoring work.
Compare runtime only after checking successful solves and the intended branch. A single refinement sample gives useful cost context but does not establish a repeated timing distribution.
Flux comparisons
A multi-flux campaign compares Roe, Rusanov, HLL and the current Städtke-type characteristic FVS within the same production backend. Relative flux runtimes use characteristic FVS as the reference and require the same case, mesh, reconstruction and Newton cap. Different fluxes generally converge to different discrete roots; matching the analytical branch and refinement matter more than roundoff-level agreement.
The existing analytical suite uses perfect-gas reference cases. Nonideal PH-pair and derivative tests separately establish the Roe thermodynamic contract. Averaging, acoustic entropy correction and strict invalid-face rejection are recorded in each Roe result.
Old versus current implementation
The native baseline is preserved pre-integration production code. It retains its own physical boundary formulas, mesh conventions, correction scaling, and numerical kernels. The current implementation uses the shared finite-volume model interface.
Matched CFL and Newton caps do not make every remaining numerical decision identical. The effective protocol below records those differences. Speed ratios measure complete solves under that protocol; they do not isolate abstraction overhead.
Performance regression monitor
A future campaign can be compared with a saved summary through --baseline. Comparisons require matching physical case and numerical settings. Machine or environment differences are highlighted; a ratio alone does not identify a code regression.
The default alert threshold is a current/baseline mean-time ratio of 1.15. Failed runs remain failures and are excluded from success-based speed claims.
